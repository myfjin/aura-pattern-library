# `build_patterns_index.py` — regenerate PATTERNS_INDEX.md

Walks the signed subtrees, reads one description per file under the **frozen 2026-07-18 ruler**, and writes `PATTERNS_INDEX.md`: one clickable row per pattern file with its description and its language twins.

It is the **browse surface** for the library. Readers find patterns through this file.

---

## What question does it answer?

> *"What are all the patterns here, and what does each one say about itself?"*

The index can never drift from what the code actually says — descriptions are extracted from the files themselves at generation time, not transcribed. A pattern with no description shows `—` rather than an invented summary.

---

## Dependencies

- Python ≥ 3.10 only. Standard library (`ast`, `os`, `re`, `glob`, `collections`).
- **No folder-nature required** — this is the one Layer-1 tool that does not need the signing stack. It only reads, never signs.
- No toolchains required.

That makes it the one tool a user can run against a fresh clone without installing anything else.

---

## CLI

```
python3 build_patterns_index.py
```

No flags, no arguments. Writes `PATTERNS_INDEX.md` next to the script.

Prints a one-line summary on completion:

```
wrote PATTERNS_INDEX.md
  1550 files · 1074 unique IDs · 9 shelves · 145 categories · no-description: 0
```

Exit 0 on success. The `no-description` count is the honest readout — if it is > 0, N patterns have no description and the index shows `—` for them; that is a cleanup task, not a bug.

## The frozen ruler (2026-07-18)

**Where the description comes from, per language — the ONE rule that fixes it:**

| lang | description source |
|---|---|
| python | `ast.get_docstring(mod)` — the module docstring, i.e. the first string statement of the file |
| cpp / go / rust | the first real comment block after any watermark + structural lines (imports, `use` statements) |
| r | the `#` block at the top above the watermark |
| javascript | the first real `//` comment block after the watermark |

**Python's trap, 35 files had this exactly:** a module-level string is only a docstring when it is the **first statement**. Put `import math` above it and `__doc__` is `None` — the text is visible to a human and invisible to every tool. Fix: move the string before any imports (after the shebang if present), above the watermark.

The ruler is frozen because the audit sheet (`library_audit.py`) and the pattern-scoring validators read descriptions the same way; a change here would silently reinterpret the entire corpus. If the ruler ever moves, every description-dependent check moves with it, deliberately.

---

## What it reads

- Every file under the six language subtrees (`python/`, `r/`, `cpp/`, `rust/`, `go/`, `javascript/`)
- `_quarantine/QUARANTINE.md` — to know which IDs to exclude
- No manifest, no catalog — the index is a function of the files on disk, not the recorded metadata

---

## What it emits

**`PATTERNS_INDEX.md`** — grouped by shelf and category. Example row:

```markdown
| [`cpp/data-science/streaming_and_sketches/hyperloglog_distinct.cpp`](cpp/data-science/streaming_and_sketches/hyperloglog_distinct.cpp) | Count distinct elements with HyperLogLog… | twins: python |
```

Each row carries:
- a clickable relative link to the file
- its description (clipped to 180 chars)
- the other languages that share its ID (the "twins" column)

The whole file is ~400 KB — large for a markdown page because it is a one-stop browse surface. Readers scan it directly; agents parse it when answering *"is there a pattern for X?"*.

---

## When to run it

- **After adding or removing any pattern file.** Even if the file hasn't been ingested yet, running the index refresh keeps the browse surface accurate.
- **After fixing a description in-place.** The index does not auto-regenerate on edit; the ruler reads the file fresh at run time, but the markdown is static until you re-run.
- **In CI, on every PR that touches a signed subtree.** Enforce that the committed `PATTERNS_INDEX.md` matches a fresh regeneration — the diff tells you whether the index was stale.
- **Before shipping a release.** `PATTERNS_INDEX.md` is a user-facing document; a stale one is a worse first impression than any pattern-level flaw.

---

## Known limits

- **Does not grade.** A pattern with a well-written description still may be broken; the index does not care. Use `library_audit.py` and `polyglot.py` for grading.
- **Does not update `CATALOG.md`.** The catalog is ID-keyed and regenerated by the ingest flow; this tool only touches the index.
- **One-run, serial.** 1,500+ files take a second or two on a modern box; no parallelism needed.
- **Rooted at the script's directory.** Move the script and the index points at nothing.
