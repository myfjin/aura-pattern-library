## New holes

### Hole 1 — R3 false-FLAGs legitimate equal-param inputs

**What R3 does:** makes the first two numeric parameters equal and counts any finite/non-empty output as "silent acceptance" (`n_accept += 1`).

**Problem:** equal params is often **valid input**, not a bug. Example: a function with two probabilities `p1=0.5, p2=0.5` is a perfectly meaningful call. If it returns a finite number, R3 marks it as "silently accepted a domain violation" and contributes to FLAG.

**Why it matters:** This will inflate the 328 FLAG count with patterns that did nothing wrong. It turns a targeted E002 recipe into a blunt "any two equal numerics" probe.

**Fix recommendation:** R3 should only count as acceptance when the equal-params input produces an output that violates a known invariant (e.g., division by zero not raised, or output is identical to baseline despite the param change). Without an invariant, R3 should be `NEEDS_ORACLE` / no-judgment, not a FLAG contribution.

### Hole 2 — token_bucket_limiter's real unbounded-burst bug is missed

**Pattern:** `python/system-administration/resource-guards/token_bucket_limiter.py`

**Exam verdict:** `INVALID` (unbounded burst after idle).

**Generic executor result:**
```text
FLAG     token_bucket_limiter.py
reason: no_positive_oracle
detail: token_bucket_limiter: FLAG [accept=0 reject=0]
```

**Why missed:**
- The function has one param `tokens_per_sec`, which is not in `DOMAIN_ATTACKS`.
- Domain-aware map has no attack for it.
- `-1e9` on `tokens_per_sec` returns a negative-token bucket, but that's a visible-nonsense state, not the real capacity bug.
- The real bug requires **stateful sequence**: idle 100s → burst 1000 ops → all granted. No single-call recipe catches this.

**This is a genuine silent-acceptance the tool misses.** The tool correctly says "I can't verify" (FLAG), but it does not find the bug. A reviewer might read the FLAG count as "needs review" and never review this specific pattern.

**Fix recommendation:** Add R13 state-sequence support to the generic executor for patterns identified as stateful (manifest metadata or heuristic). Or route all resource-guard / stateful patterns to hand-probe.

### Hole 3 — baseline arg builder too coarse → patterns with real bugs SKIPped

**Patterns affected (from exam):**
- `bayesian_iii_approximate_inference/bayes_factor_normal_means.py` → SKIP: "cannot build valid baseline args"
- `system-administration/secrets-credentials/ttl_cache.py` → SKIP: "cannot build valid baseline args"

**Why:**
- `bayes_factor_normal` signature likely has `data: list[float]` and `prior_var_h1: float` — but the type annotation may be missing or complex, so `_valid_for` returns `(None, False)`.
- `ttl_cache` returns a class instance; the discoverable entry function may be `ttl_cache(ttl_seconds=100, clock=None)`, which is buildable, but maybe other public functions confuse it.

**Why it matters:** When a pattern is SKIP, the tool does not examine it. Bugs that are known (bayes_factor wrong-math, ttl_cache size lie) are only caught because `judge()` falls back to hand-probes. **In a generic-only sweep, these would be invisible.**

**Fix recommendation:**
- Add richer type parsing to `_valid_for` (handle `List[float]`, `Optional[...]`, `Tuple[...]`, class types).
- For patterns that remain SKIP, the report should explicitly say "unbuildable args — routed to manual queue" and require a hand-probe or manifest entry.

### Hole 4 — output-acceptance detector misses set/dict degenerate shapes

**Pattern:** `python/data-science/composed_tools/dedup_pipeline.py`

**Attack:** `shingles("hello world", k=0)` → returns `{""}` (a set containing empty string).

**Generic executor result:**
```text
FLAG     dedup_pipeline.py
reason: confident_output_no_oracle
detail: dedup_pipeline: FLAG [accept=0 reject=10] ...
```

**Problem:** `accept=0` even though `k=0` was silently accepted and produced a degenerate output. The reason is `_finite_or_full`:
```python
def _finite_or_full(x):
    return _finite(x) or (isinstance(x,(list,tuple,dict,str)) and len(x) > 0)
```

A set `{''}` is not `list/tuple/dict/str`, so it's not counted as "full". The E009 degenerate-param signal is lost; the pattern only flags via "no oracle".

**This is not a false verdict** (FLAG is still correct per exam), but it is a **loss of signal**. The tool cannot tell Illia *why* it flagged dedup. It just says "I can't verify."

**Fix recommendation:** Include `set` and other collection types in `_finite_or_full`, or better, add a dedicated degenerate-output detector: if a param named `k`/`window`/`breaks` is set to 0 and the output is a small/empty collection, emit `silent_degenerate_output`.

---

### Hole 5 — domain-aware map misses many param-name families

Current `DOMAIN_ATTACKS` covers: `p1/p2/prob`, `alpha`, `rate/lambda/beta`, `u/quantile`, `var/sigma/std`.

**Missing families found in the library:**
- `tokens_per_sec`, `rate_limit`, `throughput` → positive rate (like `rate`).
- `ttl`, `timeout`, `expiry`, `duration` → positive duration.
- `capacity`, `max_size`, `limit`, `bound` → positive size/capacity.
- `window_size`, `k`, `n`, `breaks`, `bins` → already partially covered but not consistently.
- `threshold`, `cutoff`, `epsilon` → positive small values.
- `learning_rate`, `decay`, `momentum`, `step_size` → positive numeric.
- `mean`, `mu`, `loc` → real-valued (no domain restriction).

**Example miss:** `token_bucket_limiter(tokens_per_sec=10)` gets no domain-aware attack because `tokens_per_sec` is not matched.

**Fix recommendation:** Expand the map with more param-name stems and add a fallback "positive-parameter" rule: any param whose name contains `rate`, `size`, `capacity`, `limit`, `timeout`, `ttl`, `threshold`, `window`, `step`, `decay` and whose type is numeric → attack with negative + zero.
