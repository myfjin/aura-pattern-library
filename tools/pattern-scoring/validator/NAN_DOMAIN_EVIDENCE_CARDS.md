## THE SHARED ROOT CAUSE — the NaN comparison trap

15 of the 23 kills are the same bug, and it is worth naming once:

```python
return var * n / (n - 1) if var > 0 else 0.0      # NaN > 0  is False
return (mean - rf) / std_dev if std_dev > 1e-14 else 0.0   # NaN > 1e-14 is False
```
**Every comparison against NaN is False**, so the defensive `else` branch fires and the
function returns a confident **0.0**. The guard written to make the code safe is exactly
what converts unreadable data into a fabricated number. A NaN-poisoned return series
reports Sharpe = 0.0; a NaN-poisoned sample reports variance = 0.0 ("all values identical").

Equality has the same hole: `confusion_matrix` compares `y_true[i] == 1`, NaN fails every
branch, and the poisoned row is **silently dropped** — cells sum to 5 for 6 inputs while the
matrix still looks complete.

## Honest limits of this pass

- Verified by hand on a 4-case sample (`naive_variance`, `sharpe_ratio`, `fixed_n_test`,
  `confusion_matrix`): **4/4 real**. The other 19 are machine-classified, not hand-read.
- Two false-kill classes were found and fixed DURING this pass, which is why the count
  moved 45 → 23: (a) the executor's `_has_nan_out` does not recurse into dicts/sets/arrays,
  so visible poison in a dict key read as a silent kill; (b) no attack-reachability guard,
  so no-op attacks on unused params counted as kills. Both now handled.
- `Inf` absorption is deliberately NOT a kill: `tricube_weight(inf) == 0.0` is its documented
  contract. Only NaN — which means *unknown* — is conclusive.
- Nothing here was written into the library. No pattern was demoted, quarantined or edited.
