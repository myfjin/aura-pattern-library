## Finding 1 — FALSE-PASS: `power_analysis_sample_size.py` would be wrongly PASSed on p1=1.5

**Pattern:** `python/data-science/statistical_modeling/power_analysis_sample_size.py`
**Probe behavior:** `probe_power_analysis()` passes `p1=1.5` (out of [0,1]) and reports `raised=False, output=1, oracle_coverage={"mechanical": True}`.
**What actually happens in the function:** `sample_size_two_proportion(1.5, 0.5, 0.05, 0.80)` silently returns `1`. It does NOT raise.
**Tool verdict:** `PASS` (because no KILL signal fired and "mechanical" oracle coverage is declared).
**4Q predicted verdict:** `INVALID` or at minimum `FLAG`. A parameter outside its documented domain was silently accepted and produced a confident number.
**Disagree.**
**Mechanism failure:** `verdict_from_signals` treats `oracle_coverage={"mechanical": True}` as positive oracle coverage sufficient for PASS. But "mechanical" only means *recipes were run*, not *any correctness claim was verified*. The silent acceptance of `p1=1.5` should be a KILL signal (it is analogous to E003: probability out of [0,1] accepted silently).
**Guardrail that failed:** 5S's `oracle_coverage` floor. It conflates "we attacked" with "we can vouch for the output."
**Suggested fix:** "mechanical" coverage alone must NOT justify PASS. Only "numeric" or "semantic" or invariant-backed coverage should. When a recipe (e.g., R1/R2 domain) fires an out-of-domain value and the function returns a finite number without raising, the signal should be `silent_acceptance_of_invalid` → KILL, not `confident_output_unproven`.

## Finding 2 — attack-reachability guardrail works, but only when probes are honest

**Simulated scenario:** poisoned initializer that is overwritten before computation (`reached=False`), clean and poisoned outputs identical.
**Tool signal:** `attack_did_not_reach` → `NO_JUDGMENT`.
**Verdict:** `PASS` (no KILL signals, has mechanical oracle coverage).
**4Q assessment:** Guardrail works as designed.
**Risk:** the guardrail cannot detect a probe author who forgets to set `reached=False`. If a no-op probe mistakenly sets `reached=True`, the identical-output check fires `output_identical_to_clean` → `INVALID`, which would be a false-KILL on a healthy pattern.
**Guardrail gap:** no automated probe-honesty check that the poison actually reached the code path. Need static/dynamic confirmation that the mutated variable is read before being overwritten.

## Finding 3 — no-oracle plausible-number pattern correctly FLAGS, unless a probe lies about coverage

**Simulated scenario:** pattern returns `0.73` with no error, no oracle, no invariant.
**Tool verdict with honest probe:** `FLAG` (reason: `confident_output_no_oracle`). Correct.
**Tool verdict with probe declaring `oracle_coverage={"mechanical": True}`:** `PASS`. Wrong.
**4Q assessment:** This is the same root as Finding 1. The `oracle_coverage` check is the single point where false-PASSes enter. Any probe can falsely claim mechanical coverage and slip a silent acceptance past the guardrail.

## Finding 4 — concurrency boundary cap works in oracle.py, but no probe exercises it

**Simulated scenario:** concurrency pattern, single-threaded lucky run returns a finite number.
**Tool verdict with `concurrency_ordering=True`:** `FLAG` (reason: `ordering_unverified_by_execution`). Correct.

## Finding 5 — twin-divergence is recorded in exam.json but not detected by the tool

**Observation:** `exam.json` expansion records `twin_of` for 4 cpp files, including `gradient_boosting_stumps.cpp` with verdict `FLAG` because it diverged from Python.
**Tool behavior:** `validate.py` has no twin-divergence detector. It compares whatever probe result it has to the exam verdict. For all 4 twins, the tool currently says `SKIP` because no cpp probe exists.
**4Q assessment:** The spec says "verify, not assume" transfer. The tool does neither for v1 — it has no probe and no structural-diff module. This is an honest SKIP, not a false-PASS, but it means the twin-transfer efficiency is not yet exercised.
**Guardrail gap:** need v1.5 structural/AST diff + behavioral confirmation before inherited verdicts.

## Finding 6 — `stacking_ensemble.py` probe short-circuits the oracle

**Probe behavior:** `probe_stacking()` runs `BaseModel1.fit()` with NaN, observes no exception, and sets `nan_absorbed_silently=True` and `invariant_broken=True`.
**Oracle signal:** `classify_signal` sees `invariant_broken=True` and returns `KILL_or_FLAG_signal`. With `oracle_coverage={"semantic": True}`, `verdict_from_signals` returns `INVALID`.
**4Q assessment:** The probe is doing the oracle's job by declaring `invariant_broken`. This is acceptable for v1 proof-of-loop, but it makes the probe author responsible for correctness. If the probe author misclassifies, the tool has no independent check.
**Suggested v1.5 improvement:** separate probe (data collection) from oracle (judgment). Probes should report raw outputs; a generic oracle should compare NaN-poisoned run vs clean run to decide noise-identity.

## Summary of tool honesty

- The 8-signal oracle and the verdict ladder are mostly sound.
- The biggest real false-PASS risk is `oracle_coverage={"mechanical": True}` being treated as positive coverage.
- The no-oracle fall-through to FLAG works correctly when probes are honest.
- Attack-reachability and concurrency-cap guardrails work when their flags are set correctly.
- The tool has no automated way to verify that probe-reported flags are honest.

## Proposals (from this test)

1. **Demote "mechanical" oracle coverage.** It should contribute to evidence but not satisfy the PASS oracle-coverage requirement. PASS should require numeric, semantic, or invariant-backed coverage.
2. **Add `silent_domain_acceptance` KILL signal.** When a domain recipe (R1/R2/R4/R5/R9) fires and the function returns a finite/output-with-content without raising, treat it as a KILL (not NEEDS_ORACLE), because the contract was violated silently.
3. **Probe-honesty gate.** Add a layer that checks probes: for `reached`, for `clean_output` comparison, for whether `invariant_broken` has a justifying signal. This is 5S's harness-honesty gate applied to the tool's own probes.
4. **Concurrency probe in v1.** Wire `atomic_spinlock.rs` to prove the third-boundary cap actually fires.
5. **Twin-divergence module v1.5.** Before any inherited verdict, run a structural diff and behavioral smoke test; flag divergence for independent audit.
