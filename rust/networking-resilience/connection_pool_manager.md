Connection pool with a max size and idle-timeout eviction, driven by an explicit
clock (`now`). try_acquire first evicts connections whose idle age has reached the
timeout, then hands out a new connection only if the pool is under max_size, else
None. Use to bound how many concurrent connections exist while reclaiming stale ones.
Guarantees: size never exceeds max_size; connections idle past the timeout are
dropped before the cap is checked, so eviction can free a slot in the same call.

## Guarantee

When it runs, connection pool manager guarantees assert_eq!(pool.size(), 3, "Pool has 3"); assert_eq!(pool.size(), 3, "Pool still has 3"); assert_eq!(pool.size(), 1, "Old connections evicted") (proven by rustc-run).

**Checkable constraints:**

- `assert_eq!(pool.try_acquire(0), Some(0), "First acquire")`
- `assert_eq!(pool.try_acquire(0), Some(1), "Second acquire")`
- `assert_eq!(pool.try_acquire(0), Some(2), "Third acquire")`
- `assert_eq!(pool.size(), 3, "Pool has 3")`
- `assert_eq!(pool.try_acquire(0), None, "Fourth acquire fails")`
- `assert_eq!(pool.size(), 3, "Pool still has 3")`
- `assert_eq!(pool.try_acquire(150), Some(0), "Pool cleaned, can acquire after eviction")`
- `assert_eq!(pool.size(), 1, "Old connections evicted")`
